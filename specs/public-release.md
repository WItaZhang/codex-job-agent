# 公众交付规格（决定 27）

本规格是 [总规格 §1/1.1/2](../spec.md) 的公众目标及验收依据；原因见[总决定 27](../spec.decisions.md)，本轮计划见 [public-release.plan.md](public-release.plan.md)，证据与交审见 [public-release.review.md](public-release.review.md)。这是一份已批准目标的规格，不是实现完成声明。

## 1. 产品与发布判断

产品是可安装、本地优先、面向非开发者的完整求职工具。用户通过界面完成初始化、资料/意图输入、岗位发现、反馈/校准、清单、求职信、填表、本人确认或按个人授权提交、停止/恢复、历史、备份与升级。保持 A/B 数据边界和真实性；不以让用户自行写 YAML、使用 MCP/CLI 或全手工填表替代完整目标。公众运行不得依赖用户手装/登录 Claude Code；R2b 负责可替换真实 provider、确定性受限编排和用户可见服务配置。不默认建设多租户云。

**当前结论：公众发布不通过。** 核心领域及恢复有合成回归，安装资源、UI、每用户授权、可靠提交执行边界等仍有阻塞。以下状态基于 main ef8dbd3 和交审所列证据；“待验证”不等于通过，也不把尚未发现的风险写成已发生事故。

§9 的每周 200、成功率、每日人工时间和连续两周业务目标原样保留；met 只表示数量/成功率。工程回归通过、完整 B 业务验收、公众发布验收分别记录。公众发布必须有全部阻塞项完成的证据、完整用户旅程及独立验收，不能仅凭本地测试数量、制品可构建或个人委托通过。真实业务指标未证实不得宣传为已达标；本规格不授权真实投递或采集个人数据。

首发支持平台须在制品验收后声明版本/架构范围；现有证据只有本机 macOS、已有 Python 的隔离 venv，不能称为干净 OS 安装验证。可以分平台发布，不能因缩小平台范围删掉完整业务功能。UI 采用桌面壳或本地服务的具体技术选型留在 R2；若使用本地 HTTP，也要验证仅本机访问、请求来源和会话隔离。

## 2. 用户和执行边界

1. 每个公众用户从未授权状态开始，服务端/执行入口按该用户与工作区的实际授权核对资料外发、浏览器操作、普通提交、邮件动作等范围；界面清楚显示、可撤销。作者的决定 25、宿主 allow/approve、模型的 actor/source 或一个任意可写的 consent 文件均不是新用户身份与授权证明。具体信任边界在 R4 设计和对抗验证；不承诺抵御拥有整台机器完全访问权的恶意宿主。产品自身读取岗位内容的 agent 在威胁模型内：无 shell/通用文件写权限，不能写授权库、名单或调用 UI 本人确认/解除通道，必须用技术隔离和岗位注入回归证明，不能靠模型自律。
2. 资料由本人提供并核对；真实 label 只来自本人，代理选择留自己的来源和 proposal ID。缺事实显示缺失，不能补造。授权服务使用不等于授权改个人事实或移除保护名单。
3. 不自动复制日常 Chrome 或其他工作区浏览器资料。新用户使用应用专属空会话，显式登录；连接须核验浏览器归属，不能看到 9222 有服务就接入。邮箱账号/凭据的实际存储及作用域须验证，当前“Gmail 全局凭据”只是待核实风险。
4. 保护公司完整目标是**安全填到提交前、本人明确确认后提交**；未知公司/名单不可取得时拒绝自动提交。名单只按本人明确请求增删；实际观察快照、历史保护、执行时重查继续有效。当前至R5前仍由用户在保留页面手点；R5目标为本人确认后由受限入口提交，填表agent本身永不提交。本人确认绑定具体岗位、当前资料和有效状态，失效/变更重新核对；模型不能伪造确认。网页和邮件都适用。
5. 当前 browser_evaluate/click/press_key 等能力可发起副作用，prompt、按钮文字过滤、已知 submit URL 黑名单和 maybe_submitted 事后检测都不足以证明上述边界。R5 必须定义明确支持范围、受限执行与最终动作校验，并以合成接收端证明未授权请求为零；不认识的站点/动作、边界失联或无法分类均失败关闭。
6. 未完成可靠边界时可临时禁止接触真实申请页并只准备材料（L0），但这是阻塞/降级状态，不能算完整公众目标完成。不能以“保护公司永久全手填”或“只拦几个已知 URL”达成上市验收。不支持的站点可明确拒绝，并提供原因；所声明支持范围内必须完成完整目标。
7. 始终保留禁止破解验证码、接受仲裁、填写 SSN/支付、伪造答案和绕过宿主强制审批等边界；填写 agent 仍不自行提交，由受限确认执行路径完成最终动作。移除个人开发确认不扩大 agent 工具权限。
8. 结果不明与成功、失败分别展示；断线/崩溃后不自动重投未知结果。停止/撤销后的新动作须在执行边界被拦，已发送动作无法撤回须如实显示。

若R2选用本地HTTP界面，R2/R4必须验证仅loopback绑定、Host/Origin校验、用户会话、写操作CSRF保护及无通配CORS。失败例包括恶意网页跨站POST、伪造Host、无令牌读取隐私/写状态、过期会话、双工作区串用令牌；授权/解除保护接口不能由普通MCP模型工具代签。localhost、source=user或简单文件标记不是本人认证。威胁模型区分可信本机OS用户与同权限程序，不能声称隔离所有同权限进程。这是后续HTTP设计条件，不判定当前stdio MCP存在HTTP漏洞；本片不选UI技术。来源见交审记录。

### 2.1 R5 支持范围与证据分级

- E1：本地合成接收端及脚本化对抗（点击、Enter、JS请求、新窗、邮件等）是必要证据，不能单独证明实际ATS支持。
- E2：每个声明支持的ATS还须取得官方许可sandbox、自有测试组织或供应商明确允许的等效环境；由协调者核实服务条款/许可、测试账号与合成数据范围并留证。能否获得、费用、权限和条款均待验证，不预设存在免费试用或可创建测试岗位。
- E3：在E2环境用合成申请者/测试岗位核验实际收发、无确认拒绝、有绑定确认的单次提交、失效/撤销/中途名单变化、结果不明的恢复。记录版本/支持范围、发送与接收证据及失效条件，不向真实雇主投递。R5必须通过E1与对应ATS的E2/E3，R8独立复核；无获准环境不宣称该ATS支持，仍保留完整目标和发布阻塞。
- 仅允许R5测试所需fixture捕获/回放；公开脱敏fixture可进回归，凭据/原始私人记录不入仓库。这是测试范围例外，不全面解冻填表2b重放产品或2c功能。当前规格修改不执行上述访问；后续按已核实许可安排。

## 5. 下一实现片 R1：具体契约、样例及文件责任

**范围**：脱离源码的初始化、运行资源定位、用户数据目录隔离、实际制品回归及CI。初始化为本地操作，不访问网络、不启动浏览器/MCP外部工具/投递、不读作者档案；不设计 consent.json 或实现授权系统。R1新workspace在R4/R5发布门槛完成前仅本地初始化/本地读/合成测试可用；服务端对真实模型外发、网站/浏览器、邮件、投递及恢复入口明确拒绝，直接调用也必须拒绝，不能仅靠review_first、提示或隐藏UI。显式legacy config保持开发者兼容而非公众默认，不能由新workspace自动降级到legacy绕过；外部legacy配置的data_dir/db_path及直接适配入口实际路径若解析到标记workspace或其后代也拒绝。CI产物标内部预发布，不上用户下载渠道。R1通过仍不能公开自动业务。

**拟定最小接口**（后续实现按此写失败测试）：`intent-job-agent init [--workspace PATH]` 创建空工作区并报告绝对路径及“尚未配置个人资料/业务权限”；省略路径使用平台用户应用数据目录下默认工作区。MCP新增 `--workspace PATH`，不带定位参数使用同一默认工作区；未初始化时报可操作的初始化提示、非零退出，无 traceback/静默回落。form_fill report 同样支持 `--workspace`；无对应录制只报缺失，不访问网站。界面未来复用这些初始化/定位服务，用户不需掌握命令行。

**兼容语义**：保留显式 `--config` 旧入口，config 参数相对路径仍相对调用 cwd，旧配置里的相对路径仍保留既有 cwd 意义，不隐式迁移。新 workspace 模式全部路径锚定工作区，与 cwd 无关；生成配置使用绝对可写路径，包内默认资源只读。`--config` 与 `--workspace` 同传报歧义错误。已有 form_fill `--data-dir` 显式覆盖保留原语义，测试说明其优先级；用户主动指定的外部目录不能被称为默认隔离保证。不得凭目录名猜测作者 data/local；不修改显式旧配置。运行时写入包目录禁止。

初始化保留已有文件，重复运行幂等；损坏、不兼容配置、无权限或目录冲突明确失败，不覆盖、不换工作区。新建不植入真实个人资料/意图/密钥/登录态，也不生成表示同意的授权记录；名单缺失与显式空名单不能混为一谈，资料未配置时准备投递仍拒绝。包内通用默认不应含作者的搜索偏好或绝对路径。

资源须覆盖完整运行引用：default配置所需数据、通用求职信 SKILL.md 及 references 等引用文件、现有vendor YAML；需要由运行时消费的其他说明先列清单。skill唯一源仍在 .claude/skills，只允许构建时派生资源并验证一致，不复制第二份人工维护正文。宿主个人允许策略不能随资源一并作为新用户授权。资源加载可用包资源接口，不能依赖 site-packages 父级的 .claude。
