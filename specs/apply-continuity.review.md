# 连续投递与重复启动保护审阅

协调者按总决定 41、填表决定 44 完成本片实现与审阅。范围是已证实的旧 /apply 只填恢复重填、独立 start 对未完成任务重复访问，以及恢复证据覆盖；不替换执行器，不推进 Dreaming、知识库或公众 runtime。所有测试使用合成档案、临时数据库和替身浏览器；本片没有访问真实招聘网站或读取真实个人档案、密钥、验证码、私人截图和日志。

## 样例与回归

- 初始十项失败先记录在 `/tmp/apply-continuity-red.log`，涉及跨会话重复启动、换岗位编号、重复重开指令、原页接续、身份丢失及关闭失败。实现后补齐执行前竞态、原页在执行器中失效、同批次多次接续和旧录制缺来源编号；二十项专项用例通过，日志 `/tmp/apply-continuity-20-cases.log`。
- 原页接续、保护公司动态变化、工具服务中断恢复、既有填表等相关回归 299 项通过。原测试中“身份缺失自动重开”的断言按新规格改为保留 held；保护公司测试改用有代码关闭证据的合成记录，仍检验准备后名单变化和缺名单不会提交。
- 独立访问以规范化地址的录制索引去重；共享 activity 内执行前复查。重新开始绑定最新运行和真实原因，新访问后旧来源失效。未知、损坏、尚未完成的记录不当作首次访问。旧索引缺来源岗位编号时不猜测。
- 原页恢复同时检查浏览器 generation、保存的 CDP id、唯一地址和站点范围。提交执行器在启动前再次核验。未知身份不冷启动；失效时原 held 不丢失、不增加一次业务失败。只有确认代码关闭成功才写 `closed_by_runner`；数据库旧记录默认不具备该证明。
- 每次只填接续有独立 run、来源链接、attempt 和报告。批次摘要索引全部尝试，同一岗位以最后一次为当前状态，避免同一轮等待后继续覆盖证据。回执先查、保护公司仍停在提交前、填表工具权限与隐私边界保留。

## 限制

减少重复启动有确定性测试支撑；“每次动作后先观察再决定”的节奏来自执行提示，不能当作宿主对每次点击的强制保证。未测量真实网站验证触发率，不能保证不再出现人机验证。浏览器身份丢失时保守报告阻塞，确需从头开始仍须有真实请求或授权范围内的依据。

业务会话已确认上一片的 radio 识别、普通截图可见及同地址进度修复有效；它追加的页面标题、局部弹窗汇总、WOTC 题目映射问题仅作为独立后续证据保存，不纳入本片，也不把停在独立签名步骤说成申请已完成。
