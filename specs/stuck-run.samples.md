## 一、一步一定能结束

### S1 agent 退出了，还有进程拿着输出管道

- 第 1 个岗位：填表 agent 写完结果（dry run）后退出。它启动的一个进程换了进程组，还开着，一直拿着 agent 的输出管道。
- 以前：读输出要等所有写端都关掉，这一步永远停在"运行中"。
- 现在：agent 退出后最多再读 10 秒剩下的输出，然后结束那个进程（运行中记下过它，按进程编号和启动时间认），照 agent 的结果往下做：读回、出报告、记 waiting，接着做第 2 个。

### S2 agent 活着，但一直没有输出

- 第 3 个岗位的 agent 打开页面以后，一个浏览器工具调用一直没返回，300 秒没有任何输出。
- 结束 agent 的整棵进程树（它的进程组，加上换了进程组的子孙进程）。
- 结果码 `stalled`：
  - 做过操作的（有工具调用）：failed，备注"投递 agent 300 秒没有任何输出，算卡住，已结束它"。填表报告写"没填完：卡住（填表 agent 的结果：stalled）"。
  - 一次工具调用都没有的：退回待投（`system_error`），和超时一样（第 67 条）。
- 接着做第 4 个。

### S3 一直有输出，超过总时限

- 第 7 个岗位的 agent 一直在输出，到 900 秒还没做完：和以前一样记 `timeout`（failed，算允许的"网络超时"），同样结束整棵进程树。

### S4 agent 不读输入

- agent 起来后不读指令。以前写指令那一步会一直等；现在指令从旁边的线程写，300 秒没有输出就按 S2 结束。

### S5 读标签页卡住

- 第 2 个岗位的 agent 退出后，代码读回它的标签页。页面一直不回应（例如留着一个对话框）。
- 最多 120 秒：结束这次读页的 Playwright 驱动，读回失败（`readback_failed`，备注"读标签页 120 秒没有回应"）。agent 说填完了的照第 89 条记 waiting（`unreadable`），请你逐栏自己看。接着做第 3 个。
- 接着做之前"读一眼"原标签页也一样：120 秒读不到就当没读到，照常起 agent（它会先查是否已经交过）。

## 二、停下（`stop_applying`）

### S6 第一步做到第 3 个时说"停下"

- 第 1、2 个已经是 waiting；第 3 个正在由填表模块填（停在提交前）。
- 第 3 个的 agent 马上结束。第 3 个回到待投，不写尝试记录；它的报告写"没填完：你停下了"。
- 第 4、5 个不做，留在待投。这一步的状态是 `stopped`。
- 第一步有成功的（1、2），和做完的第一步一样：你说"继续"就能开始第二步（6、7、8）。

### S7 第二步做到第 7 个（自动提交）时说"停下"

- `stop_applying` 返回"第 7 个正在自动提交，等它做完再停"。第 7 个不打断，做完按它自己的结果记（最多到卡住或 900 秒）。
- 第 7 个的 agent 还没起来时说停下（例如还在看投递用的 Chrome）：它就不起了，第 7 个回到待投（审查 #5）。
- 第 8 个不做，留在待投。这一步 `stopped`。

### S8 第一步第 1 个时就停下

- 第 1 个回到待投，2–5 不做。第一步一个都没成，也没有等你处理的：这一批作废（第 68 条）。所有没做的岗位都是待投，下一批还会选到。

### S9 接着做（resume）时停下

- 正在重填的停在提交前的岗位马上结束，仍是等你处理，去掉"正在接着做"的标记。没轮到的仍是等你处理。
- 正在接着做的自动提交岗位，和 S7 一样做完再停。

### S10 没有在跑的一步时说停下

- 返回"现在没有在跑的一步"，什么都不改。

## 三、最后活动时间

### S11 apply_status 里的时间

- 每个岗位：`started`（开始）、`finished`（结束）、`last_activity`。
  - 做完的：`last_activity` 是结束时间。
  - 正在做、agent 还在跑的：agent 最后一次输出的时间。
  - 正在做、agent 已经退出（在读回）的：agent 退出的时间。
- 正在做的岗位另有 `quiet_seconds` 和 `agent_alive`。例：第 3 个 `started 18:37:30`、`last_activity 18:41:30`、`quiet_seconds 240`、`agent_alive true`。skill 说："第 3 个已经 4 分钟没有动静，满 5 分钟会自动算卡住、接着做下一个；要现在停就说'停下'。"
- 说了停下、还在等正在做的岗位时，整步 `stopping: true`。

## 四、重启以后

### S12 第一步做到第 3 个时工具服务被重启

- 1、2 已记 waiting，第 3 个正在由填表模块填。数据库里：第一步"进行中"，`apply_running` 写着上一个工具服务（已经不在了）和第 3 个。
- 下一次 /apply 调用 `apply_status`：
  - 先结束上一个工具服务留下、还活着的 agent：父进程已是系统，命令行带着本数据目录的 `.mcp-form-fill-0.json`。
  - 第 3 个停在提交前、不会提交：留在待投，写一条尝试记录（pending、`interrupted`）。4、5 留在待投。
  - 第一步按 1、2 的结果收尾：有成功的，第二步可以开始。
  - 返回 `idle`，`next` 是这一批第二步的摘要，`notice`："上次第一步做到第 3 个（Gamma AI）时工具服务停了：第 3 个退回待投，没做的留在待投。"

### S13 第二步做到第 7 个（自动提交）时重启

- 第 7 个可能已经交了：记成等你处理，原因 `interrupted`，写一条尝试记录（held）。
- `held` 一组里：`7 Zeta Pay｜工具服务中途停了，可能已经交过｜请先在投递用的 Chrome 里看它交上了没有`。
  - 交上了：说"7 已投"，算成功提交。
  - 没交、要接着投：说"好了"。接着做的摘要写"上次中断，可能已经交过，请先看标签页"，agent 先查是否已交过。
  - 不投了：说"7 不处理了"，算一次要修的失败（`interrupted`）。
- 第 8 个留在待投；第二步收尾。

### S14 重启时没有在做的岗位

- 一步刚开始还没轮到第一个，或者最后一个刚做完还没收尾：没有要处理的岗位，只按数据库里的结果收尾。

### S15 哪些进程算上一个工具服务留下的

| 进程 | 父进程 | 命令行 | 处理 |
| --- | --- | --- | --- |
| `claude … --mcp-config <数据目录>/applypilot/.mcp-apply-0.json …` | 系统（1） | 本数据目录 | 结束它和它的子孙进程 |
| 同上 | 另一个会话还活着的工具服务 | 本数据目录 | 不碰（别的会话正在用） |
| `claude … --mcp-config /其他目录/.mcp-apply-0.json …` | 系统 | 别的数据目录 | 不碰 |
| 名字叫 claude 的其他进程 | 任意 | 没有本数据目录的 MCP 配置 | 不碰 |

### S16 两个会话共用一个数据库

- 主目录里开着两个会话，各有一个工具服务。会话 A 正在跑第一步。
- 会话 B 调用 `apply_status`：返回 `idle`，另写"另一个会话的工具服务正在跑投递的一步（batch-stuck01 第一步，从 18:37 起）"，不当作中断，不动 A 的 agent。
- 会话 B 调用 `start_applying` 或 `resume_applying`：拒绝，免得两个 agent 同时用一个 Chrome。

### S17 本切片以前留下的"进行中"

- 主目录 10-1x 的 batch-7f2ffcec8d8c 第二步停在 running，没有 `apply_running`。下一次调用时同样收尾：没做的岗位都是待投。

## 五、有人在用投递用的 Chrome

每种都只写进这个岗位的报告备注和 `apply_status` 的 `chrome_use`，整步一句 `chrome_warning`："可能有人在用投递用的 Chrome"。不停下这个岗位，不动页面，岗位照它自己的结果记。只写网站名，不写完整地址。

### S18 运行中开了一个新标签页

- 第 2 个岗位运行时，你按 Cmd+T 开了一个新标签页看 `news.example.test`。agent 只开了自己那一个。
- 写："运行中多了 1 个不是 agent 开的新标签页（news.example.test）"。

### S19 把 agent 正在用的标签页关了

- 填表 agent 运行时，你关掉了它正在填的标签页。agent 没有关过标签页。
- 写："这次运行开的标签页有 1 个被关掉了，不是 agent 关的"。之后代码找不到标签页，照旧记 `tab_lost`。

### S20 Chrome 被关掉

- 运行到 18:37:53，Chrome 被退出（或崩溃），调试端口连不上。
- 写："投递用的 Chrome 从 18:37:53 起连不上了（被关掉、崩溃，或调试端口没有响应）"。下一个岗位开始前照旧重新启动 Chrome。

### S21 开始前就开着的标签页变了

- 运行中 `T2`（你还没交的表）被关掉，`T1` 换到了 `sports.example.test`。
- 写："开始前就开着的标签页里，1 个被关掉、1 个换了地址（sports.example.test）"。

### S22 去了 agent 打不开的网站

- 这次运行开的标签页打开过 `mail.google.com`（`apply.blocked_origins` 里的网站，agent 打不开）。
- 写："这次运行开的标签页打开过 mail.google.com：agent 打不开这类网站"。

### S23 这些不算

- 网站自己弹出的新标签页（有 opener，例如点 Apply 跳到招聘系统、"用 LinkedIn 申请"的弹窗），弹窗自己关掉。
- agent 自己开的新标签页（`browser_tabs` 的 new）。
- 自动提交的 agent 做完关掉自己的标签页（`browser_tabs` 的 close）。
- 一直停在空白页、没人用的新标签页（Playwright 可能自己开一个）。
- 接着做时 agent 回到原标签页（开始前就开着），在里面接着填、交完关掉。
