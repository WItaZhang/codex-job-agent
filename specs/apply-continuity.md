# 连续投递与重复启动保护

用户要求减少重复任务、重复网站操作和卡点。本片修已证实的旧宿主路径：恢复只填任务却新开页重填，以及未完成独立填表再次被当作首次启动。不改变业务授权、个人答案或提交权限，不操作真实申请，不新增反检测或验证码破解功能。

## 行为

1. 独立填表以规范化岗位地址的录制编号识别已经访问的申请。上次未完成、结果未知或录制不完整时，`start_form_fill` 返回 `blocked` 项及已有运行编号，优先交 `get_form_fill_gate` / `resume_form_fill` 检查原页。已完成的沿用 skipped；不能仅因为上次失败就再次访问。换清单、换 job id 或重启 MCP 不清除这个保护。旧录制缺来源岗位编号时明确返回空值，不把新清单编号猜成原编号。
2. 确需从头再做时，清单必须带 `revisit: true`、与最新访问相同的 `restart_from` 和非空 `restart_reason`，由协调者依据用户请求或实际授权范围提供真实原因。记录来源及原因。新访问建立后旧 restart_from 失效，重复同一清单不再再次访问。未到浏览器访问阶段的输入校验失败不消耗访问记录。共享 activity 锁内、实际执行前再次检查，避免准备阶段的竞态。
3. `/apply` 的 held 岗位，无论 submit/review/careful，原标签页存在时均接续原页。只填路径复用既有 `run_job(resume=...)`，仍禁止提交和发信，先查回执。只接受保存的 generation + CDP tab id，不以同地址的另一标签页替代；重复地址、身份不可验证、原页丢失及站点变化保留 held，不启动执行器、不计为业务失败。
4. 用户此前选择 unattended，或在场等待按既有超时/跳过规则结束，代码成功关闭本岗位标签页后的重跑，按既有授权允许重新打开；已保存的原页突然消失不能默认为同一情况。关闭失败时保留原标签页身份，避免下一次无端重开。未知浏览器状态不能触发冷启动。
5. 每次只填接续使用独立记录目录，保留来源 run（若此前由填表模块执行）、原批次的 attempt 和最新报告；同批次多次等待后继续也不能覆盖前一次证据。批次摘要链接各次报告，个人事实与验证码不进入通用经验。
6. 执行器遵守操作顺序：一次只等待一个导航或表单动作；操作后先看新页面/错误/已接收状态，再决定下一步；页面尚未响应时不重复点击 Next、登录或请求邮箱码，遇到人机验证保留页面交本人。此为执行提示约束，不能冒称宿主已强制隔离每次浏览器点击，也不承诺消除网站验证。

## 最小切片与样例

先写失败测试：未完成任务跨 Toolbox 重复 start、同 URL 换 job id、一次重开指令复用、只填 held 在原页继续、原页失踪/同地址替身/查询失败不重开、无人值守关闭失败保留身份、连续门槛每次保存独立证据。用合成网站与替身执行器统计新页/执行次数，验证已有回执不启动 agent、权限边界不扩大。全部四项验证通过后审阅、合并、推送、清理。真实网站验证沿用业务会话授权，本片不调用真实浏览器。
