# 投递环境检查决定

## 1. 区分网页前提与邮箱能力（2026-11-09）

用户指出 Gmail 配置未完成时曾报告“准备就绪”，随后任命主会话负责开发并要求负责修复。协调者依决定 25 选择本片方案。

代码证据：get_apply_setup 的 ready 只由资料/答案计算，programs 未参与；Gmail MCP 始终加载；相关测试主要断言服务表和白名单。固定依赖 1.1.11 仅在 auth 子命令启动授权，普通服务启动不引导；调用错误还可能作为普通文本 Error 返回。

决定：保留可选 Gmail；新增有界连接检查与可操作的授权入口，复用既有 search_emails，不引入新邮箱供应商。默认检查本机状态，明确请求连接才访问邮箱。实际运行再次检查并按能力降级，沿用已有人工门槛。配置路径与真实运行共用一套解析逻辑。不开启自动授权，不读取真实个人文件做开发验收。

未选择：仅补用户电脑上两个文件（无法修复其他用户与失效授权）；只检查文件存在（不能证明凭据有效）；Gmail 不可用就阻塞所有网页申请（邮箱原本可选）；把 list_tools 当连接成功（未访问 Google API）；将真实账号接入普通单元测试。
