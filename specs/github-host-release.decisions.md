# GitHub 双宿主源码交付决定

## 1. 按用户新目标重排，不继续公众实现

用户明确取消独立上市产品，改为GitHub clone后按README在Codex/Claude Code使用；协调者批准规格完成后直接实施。保留所有代码、旧分支和历史，主线只修源码使用的文档/配置/示例及已证实旧host阻塞。不把S2新runtime/桌面功能合入，也不以此前公众验收门槛阻塞本片。

## 2. 协议实证与宿主/业务实证分开

MCP initialize/list_tools证明配置进程与协议，不证明宿主实际发现skills、派生角色或真实网站成功。合成闭环复用现有领域入口，替身只在测试；实际支持平台/版本逐项记录。新用户自己授权，作者开发委托不是所有使用者的业务许可。真实投递后端保留Claude Code/Chrome/Node依赖，保护公司规则及隐私限制不撤销。

## 3. 旧宿主跨连接恢复报告互斥

main 基线真实 resume_applying 线程与第二 Store 已复现：正在执行和队列中的岗位都可被另一宿主报告删除 hold。使用现有 apply_running 协调行增加本次选定岗位 ID 列表，与活动建立同事务持久化；不提前设置 resuming，排队仍不是已开始外部动作。报告在同一写事务内重算同岗集合，检查持久选定集合及已开始 resuming 标记；无关岗位可报告。恢复开始时在锁内复查 hold 仍存在。旧活动没有选定列表时不能推定空闲，保守保护其 held 岗位，待活动正常关闭或既有 owner 恢复处理；不新增自动重放或全局锁。活动结束释放队列保护，未确定结果的 resuming 保留既有恢复语义。

## 4. 两宿主共用源码根启动语义

Claude 原启动配置未使用 --locked，且从子目录执行时默认配置相对路径错误；实际执行配置命令的合成 uv 哨兵测试两项红。两宿主统一 POSIX sh：先 git rev-parse 找当前检出根，再 exec uv run --locked 与显式配置。保留已有工具权限，不复制宿主个人配置，不自动信任项目。README优先最短路径，浏览器/投递额外依赖及授权/升级限制按代码说明。Windows未验证，不承诺该shell路径可用。

## 5. 新用户授权与显式开发模式

开发标记位置及授权证据口径已被决定6取代。

协调者采纳基线报告B1/B2、D1–D7/S1–S3。作者现有全权委托持续有效，不再询问；新使用者的含糊/apply不授权自动提交，先完成材料/清单并只填，给出当前批次、非保护公司和自动提交范围的一次明确选择。明确自动投递当前清单本身即授权，后续沿用至撤销。保护公司仅本人手动提交，allow/approve只是工具可用性，不新增consent框架。

代码锁仅本地显式开发模式生效，普通clone无需claim即可配置/升级。现有锁表明该共享仓库已经用于受管理开发，不能因新版本而失去保护；enable-dev/claim在当前检出git目录持久标记开发模式，release不关闭模式，共享仓库只要存在任一开发标记或锁即继续按原跨检出规则执行。标记不进git、不复制给新clone；不自动改全局宿主设置。

增加本地文件忽略规则、历史plan弃用说明及去私人标识；工具说明明确路径相对源码根。每种已登录宿主最多一次受控验证会话，只合成材料/受限工具，失败记录原因，不反复重启或冒称新用户登录验证。

## 6. 持久开发模式与可查授权证据

采纳EN-1/AU-1：enable-dev/claim及旧锁release把标记写入common git目录，避免删除worktree后失去管理保护；仍兼容既有检出标记/锁。旧仓库已无任何标记/锁时不能推断开发模式，README要求显式enable-dev。授权沿用当前会话和可用宿主历史的真实明确指令；跨会话取决于宿主上下文，项目不自动记忆。没有可查证据才呈现一次具体范围，不从作者文字推断新用户授权、不重问本会话已授权用户，不新增授权存储。G03补两宿主各至多一次成功受控会话，实际skill加载/角色派生与协议、配置解析分层记录。

## 7. G10真实skill两轮合成行为验收

协调者批准：仅测试文件/包外启动器，真实Toolbox与既有GateRunner/FormFillFake、全合成材料。先无模型验证材料/runner/网络毒丸，再一场Claude持久会话分两轮输入，实际加载apply skill；不预填模型的stop_before_submit/授权模式。无既有授权的含糊调用和明确当前范围授权以实际工具参数、runner及数据库判断，同批后续只通过状态轮询推进，不再索要相同授权。保护公司每次stop。测试调度屏障只控制假runner完成时机，不改变产品权限或分派逻辑；无生产fake开关。其他宿主不重复测试。

## 8. Codex持久角色证据与本次合成线程读取

独立审查不接受002的空wait事件及父自述补足G03。协调者批准G10之后仅一次003：现有登录、--ignore-user-config、不使用--ephemeral；两角色各一次fork_turns=none，完整定义回退，无岗位/业务。先无模型确认确切thread/read及skills/list接口；仅从本次父线程返回的child ID读取对应记录，不扫描私人历史、不复制凭据或改全局配置。完整定义读取、spawn参数、child收到的任务与实际返回分别核验；若宿主将message保存为encrypted_content，不读取密钥/尝试破解，报告无法明文逐字比较，不以父自述代替。G02分层证据已获签收，app-server曾401预连接的事实保留，不宣称全进程无网络。
