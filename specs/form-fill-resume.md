# 填表原页接续与邮箱验证码交接

本片解决已证实的旧宿主填表阻塞。用户在 2026-11-09 要求主负责人继续解决业务会话的反馈；只修提示不算完成。只填不交、本人过 CAPTCHA/SSO、仲裁/SSN/支付限制不变；不实施冻结的重放和独立评审。

## 接续契约

- `get_form_fill_gate(run_id, job_id)` 返回原运行的门槛、精确浏览器 generation/标签页身份、当前可否接续及已有接续结果。使用保存的 BrowserBinding 和专用 profile，不靠应用名、前台窗口或固定端口找 Chrome。只读检查不启动 Chrome、agent 或新标签页。
- `resume_form_fill(list_path, run_id, job_id, verification_code?, code_received_at?)` 在已有业务授权内接续一个岗位，仍停在 Submit 前。清单必须与该运行保存的岗位身份一致；新运行保留来源关联。
- 原浏览器 generation 和原 CDP 标签页编号都匹配才能接续。地址歧义、原页丢失、浏览器重启、身份失效、当前站点不属于已记录申请/门槛站点时明确拒绝，不自动重开或重发码。用户确实要从头开始时使用 start_form_fill。
- 检查与启动之间再次核对身份。开始前看到申请已接收，报告该事实，不启动 agent，不推断提交者。未传验证码时先观察用户是否已手动过门槛，不凭“继续”假定已通过。
- 录制器、最终读回和其他标签页检查都认识该授权原页。原页之外的已有标签页不属于本运行。
- 页面可读不代表填完。agent_result 为 stuck、needs_answer 或其他提前停止结果时，顶层用 incomplete，不以读回字段数判成功。缺少的资格事实仍需使用者提供，不由接续或经验总结补造。

## 一次性验证码

仅 email_verification 门槛接受使用者或其已授权宿主从本次对应邮件取得的 4–12 位数字验证码；不接受 CAPTCHA 答案、任意指令、密码或 URL。接收时间必须有时区、不早于来源运行开始、不晚于现在，并在配置的交接有效期内。此时限不承诺网站自己的有效期。网站拒绝或提示过期时保留原页并报告门槛，不循环尝试或擅自重发。

验证码只在这次执行内存/子进程环境及指令中使用，不写数据库、checkpoint 配置或报告；日志先脱敏再写。checkpoint 继承一次性脱敏值，携带验证码的运行保守限制截图、原始页面及网络捕获，报告说明证据缺项。项目不能控制宿主自身保存的工具参数。结束后不保留验证码供重试。

## 并发与幂等

来源 run_id + job_id 是不可变接续键。SQLite 事务同时登记 apply_running 互斥和接续记录；并发/重复“继续”返回已有运行，不再启动第二个 agent。跨宿主重启保留关系。再次遇到门槛时用新的结果运行编号接续；中断而结果不明时拒绝自动重复执行。

独立填表不改 applications/holds/偏好；只增加接续协调记录。/apply 清单的 prepare_resume/resume_applying 已通过 [连续投递切片](apply-continuity.md) 接入同一原页执行能力，并在自己的流程里更新 held。不能用独立接续入口冒充 held 状态已更新。

## 验收

合成样例覆盖：普通 Chrome 与专用 Chrome 同开相同地址、错误 generation、原页丢失/地址歧义、Gmail 缺配置但宿主已有有效码、过期/旧码、用户已手动验证、跨 Store 并发及重复继续、已接收申请、再次遇到门槛、验证码不落盘、始终禁止发信/提交。另做本地合成网页和真实浏览器的绑定/原页读回验证；不把替身 agent 测试冒充真实网站成功。
