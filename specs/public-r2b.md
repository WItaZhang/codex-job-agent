# R2b 宿主无关模型运行时与确定性编排

依据[公众规格§4.1](public-release.md#41-r2b-运行时验收与责任)及[总决定27](../spec.decisions.md)，配套[计划](public-r2b.plan.md)、[模块决定](public-r2b.decisions.md)、[交审](public-r2b.review.md)。这是待评审的完整目标规格，不是能力已交付声明。当前只批准四文档，未批准实现。决定30属于R2，不是R2b实现编号。

## 1. 目标、现状和边界

面向非开发者，通过本地应用完成A找岗位和B投递的确定性流程，不依赖用户安装或登录Claude Code/Codex，不要求用户安装Node/npx，不在运行时下载工具包。允许已审核、列入制品清单的包内Node driver；需要记录路径、hash、许可、签名及真实进程来源，不能把所有Node进程一概当失败。

main23aa66b现有`llm.py`只有fake/host，host返回schema默认值；`engine.py`能接收宿主理解参数。四个skills承担流程编排，`apply_bridge.py`/`form_fill/runner.py`仍启动claude，MCP配置使用npx。`applypilot_bridge.py`使用另一套vendor模型环境凭据路径，但configure/run_sources已有Settings外发闸门，不能称其已绕过local_only。R2未合并，源码与006的限定验收不代表其GUI出口通过。

R2b必须交付可替换provider、至少一家真实适配和受控合成实证、完整A/B状态机、受限工具、错误/usage/取消及用户可见配置。前置纯接口、fake或单个provider成功均不等于R2b完成。公众真实外发、凭据授权和最终提交边界属于R4/R5；新workspace local_only保持，不能通过选择provider/fake、UI字段或测试开关解锁。合成工具依赖由测试构造注入，不能允许公众参数将任意URL标成synthetic。开发者legacy保留明确适配，不是公众默认回落。

当前不读密钥/profile/.env，不接账号/网站，不改skills正文、评分/回放规则、新来源、定时任务或费用账本。R2b不承担R5技术保证，也不删除最终提交目标。

## 2. 核心接口与信任边界

以下为语义契约，实施片可选择内部类型名称，但不得缩减字段含义。

| 接口 | 输入 | 输出与守卫 |
| --- | --- | --- |
| structured | request_id、节点、封闭schema、按角色分隔的消息、模型配置引用、限制与取消句柄、已声明数据类别及过滤策略版本 | validated value或固定错误；完整响应后才提交原领域schema校验，分片不是有效结果 |
| tool_turn | 同上及当前节点封闭工具schema | 有界tool_calls或final；模型请求不是执行/授权，逐项再校验注册表、状态、参数、执行身份与预算 |
| cancel | 当前request_id/执行代次 | 本地停止、传输状态、远端状态分别报告；不凭一个cancelled布尔值宣布已撤销 |
| capabilities/config_status | 显式provider/model配置，不含秘密 | 结构化/工具/取消能力、凭据缺失或已配置、服务与目的地、各节点允许的数据类别与外发对象、费用/留存告知；能力未知不可假装支持 |

模型只能在标签、原因理解/排序、意见转changes、求职信和受限填表节点提供输出。标签/changes经确定性代码提交既有校验入口；模型不可直接调用record_labels、decide、start_applying、release_careful_companies或本人确认通道，不得得到shell、通用文件写、授权库、名单写入口。工具表不提供任意URL请求或任意JS执行作为兜底。仅移除工具名称不足证明浏览器最终提交隔离；真实执行仍被R4/R5禁用。

每个请求绑定workspace/run/node/attempt及当前revision；过期结果不得写入另一工作区、下一次运行或新窗口。业务写入复用既有唯一入口、proposal ID及当前集合校验。公众流程不继承作者全权委托；真实label、偏好、个人事实必须有对应输入，`actor=user`/source字段不认证用户。合成测试命令只能证明协议，不能变成真实授权证据。输出拒绝时关键领域状态不变，允许独立非正文诊断记录。

strict适配不静默降级：只做可证明保持语义的schema转换，不把所有有默认值的非空字段改nullable。无法表达则schema_unsupported；转换后仍用原领域schema校验。不能把供应商strict保证当领域正确性或权限保证。新fake缺脚本必须明确失败，不延续旧FakeClient默认空值冒充理解完成；旧接口兼容单独回归。

### 2.1 节点数据白名单与必经过滤

每次structured/tool_turn请求（含fake、重试、历史消息和工具结果）必须经过确定性组装和打码边界，再交provider。S1即实现非可选策略，不是可绕过的空钩子：未知节点、未声明类别、越权字段拒绝；缺策略/过滤失败不发送。调用方不得直接拼入原始个人文件或任意prompt绕过；模型没有读取个人文件的工具，不能自己扩大类别。类别声明来自代码白名单，不信模型自报或把所有数据标成“岗位”。以下是允许上限，不意味着自动获准真实外发，仍受R4授权和local_only约束。

| 节点 | 允许进入请求的数据 | 确定性排除/最小化 |
| --- | --- | --- |
| 发现增强 | 本次岗位/招聘板公开文本、提取schema、已选择的搜索条件 | 不含申请者档案、简历、label历史或联系方式；页面文本中的联系方式按与任务无关的联系字段打码 |
| 岗位标签 | 本岗位文本、封闭维度/词表及标签规则 | 不含个人意图、反馈、简历或投递资料；公开文本仍不可信，联系字段打码，不允许通过文本指令读文件 |
| 原因映射/排序、意见转changes、显式意图修改 | 相关意图条目/词表、相关label与用户意见、岗位标签和候选cause/proposal摘要 | 默认不传简历；确有既有规则需要的摘要先打码，仅经声明的非联系方式事实；用户自由文本也须打码，不带联系方式/账户标识或整份档案 |
| 求职信 | 既有get_cover_letter_materials/get_resume材料白名单中的岗位、必要经历及规则；既有材料授权允许的信头最少字段 | 不新增profile读取；不直接传整份profile，不带与信件无关个人字段。联系方式只限既有授权信头字段，不因本规格扩大材料权限；缺材料报告缺失 |
| 受限填表 | 当前岗位/表单、当前动作所需的已授权投递字段与必要附件引用 | 只由既有受限资料服务提供最少字段，模型不得读取profile.json/.env或任意文件；不整份传递资料；验证码、SSN、支付、仲裁等原限制保留；秘密/会话凭据不入prompt |

编排器只取声明字段，丢弃无关上游字段；若请求仍夹带未声明类别则拒绝。联系信息和简历哨兵的确定性打码必须覆盖实际序列化消息，不只测metadata；日志仅记策略版本/类别/拒绝码，不存打码前正文。对已知结构化个人字段逐字段过滤，自由文本按可测试规则打码，不宣称识别所有自然语言秘密。S2/S3可以细化所需字段，但不能在S1之后才补这道边界；新增类别须先规格和审阅，不能由模型动态注册。

### 2.2 面向消费者的协议版本

S1定义事件、命令、错误、usage、取消统一封套protocol_version=1、request/run/node/revision关联与能力声明。版本不是权限。v1拒绝未知命令/字段/错误枚举和不支持版本，不静默执行或降级；消费者显示固定“不支持的协议版本，请更新兼容组件”，不猜状态。新增可选字段也需发布方与消费者显式支持版本/能力并有兼容测试；破坏性语义变更升主版本，持久化旧事件只能用明确适配读取，不重放副作用。缺版本、跨版本及旧revision作为合成消费者反例。旧LLMClient/FakeClient/NoModelClient与MCP host接口保留独立兼容路径，不把旧接口强行当新v1。

## 3. 错误、取消、用量及重试

固定错误至少包括missing_credential、invalid_credential、unsupported_model、schema_unsupported、schema_violation、refused、incomplete、timeout、rate_limited、network、permission_denied、stale、budget_exhausted、internal。错误返回固定中文原因/相关配置项/下一步，不含key、原始响应、个人正文、任意异常路径。缺key只针对真实适配，fake无需key；不回退作者环境、宿主登录或其他账号。

取消是多维事实而非互斥成功标签：例如`local=stopped, transport=aborted, remote=unknown`同时成立。远端已确认取消需要provider实际确认，传输中断不是确认，远端取消也不回滚已经发生的工具副作用。重复停止幂等；模型后续结果丢弃，停止后不发新节点。纯理解节点可重新请求但费用仍可能发生；工具已launch且结果不明按既有held/interrupted/maybe_submitted核查，不回pending自动重投。未launch不能伪造已执行。stop与身份失效优先序、R1b generation/归属和恢复已提交核查继续有效。

| 场景 | 用户可见结果 |
| --- | --- |
| 请求尚未发送就停止 | 已停止本地处理；未发送本次请求 |
| HTTP中断、无远端答复 | 已停止本地等待；服务端处理及费用尚不能确认 |
| provider明确取消确认 | 服务端已确认取消；此前用量/工具动作仍按实际记录 |
| 合成接收端收到提交后断链 | 提交结果待核查；恢复不重复提交，不显示“已取消提交” |

请求有配置化超时、总时限、轮数、并发、输入/输出大小、重试/退避预算。达到预算返回budget_exhausted并停止新请求/动作，不自行重置预算；已launch未知结果仍进入核查，不能借预算耗尽宣称未发生。鉴权/权限/不支持不自动重试；schema修复有界；限流遵循有界退避。请求重试和业务动作重试分离，不因模型超时重做提交；中断请求可能重复计费，不能承诺exactly-once远端请求。

usage包含provider/model返回标识、request_id、尝试次数、输入/输出及可用细分token；缺失为unknown而非0。聚合不能漏掉失败/重试中已报告用量，不同模型单位不能盲加。费用仅在有对应模型/计费维度/币种/官方来源日期时估算，并标估算非账单；缺项显示未知/部分已知，不保证取消免费。fake显示模拟、真实API调用0，不将模拟token当账单。无可靠公众成本基线，不读个人历史日志。

## 4. 流程映射与确定性状态

完整fake旅程由包外测试构造器注入合成已生效意图/资料开始；这些是隔离测试前置，不把R2 setup-drafts自动转成生效数据。公众草稿生效属于R4确认与校验路径，未实现时拒绝；无合成生效前置时不得伪称完整旅程。公众输入/选择来自相应用户，个人模式仍可依决定25由已授权协调者作可追踪选择，不恢复作者逐次批准门槛，模型不能冒充任一来源。

总路径：合成生效前置/配置→搜索候选与选择→发现/标签→推荐→真实反馈→分析与选择→清单→求职信校验→准备批次→填表→提交守卫→终态/核查。每个状态只接受本状态的输入；模型不输出可执行的next_state。未知结果核查优先于重试。

| 现有规则来源 | 状态/守卫及必须保留的分支 | 先红验收编号 |
| --- | --- | --- |
| 显式意图修改 | 用户明确请求→propose_intent_edit→展示proposal/版本/摘要→有效选择→decide唯一入口；陈旧/不匹配拒绝，缺事实不猜，不允许模型直接生效 | A05 |
| fetch-jobs §1–3 | 当日状态、缺搜索配置按已有意图生成候选→awaiting_selection→按当前模式取得可追踪选择→校验候选版本并启用；公众由相应用户选择，个人模式协调者可依决定25选择，不新增作者审批门槛；无模型则明确跳过可选增强；发现/boards任务轮询，失败仍处理已有队列，错误脱敏而非原样异常 | F01/F02 |
| fetch-jobs §4–5 / job-tagger | 每日预算、粗排预筛、每批10/并发最多5受配置预算约束、job唯一分派、失败留队；报告新增/预筛/relocated/retagged/新key，不私改hours_old | F03 |
| today §1–3 | 缺当日岗位先fetch；已有label/未结分析续办；编号映射固定；+/−/?解析保留原文与理解分离，未提及不反馈，含糊等待澄清 | A01 |
| today §4 | skip/ask/ask_scope；排序不删选项，misattributed_by保留；choose_cause再proposal/summary；提意见/不改；薪资缺事实不写；stale先refresh | A02 |
| today §5–6 / apply-list §3 | misread仅修tags、same_posting准确全集合/地点不改；刷新分析与清单，不写偏好 | A03 |

| apply / cover-letter-writer | 先列held、只对缺信岗位批处理、每job唯一、校验失败不投递、有界重试；材料白名单、真实性和PDF校验保留 | B01 |
| apply准备/执行 | 默认review_first=0与显式只填保留；执行时名单重查+实际快照，未知/受保护不得自动提交；名单删除不得解除旧保护 | B02 |
| apply停止/恢复/汇报 | prepare_resume准确job_ids/summary；waiting/held/interrupted/maybe_submitted/already_applied区分；门槛解决不凭口令，已提交不重投；数值met不代表完整B验收 | B03/B04 |

发现中的smartextract/enrichment迁入显式provider注入路径；未配置时保留可选跳过并报告影响，不能永久删除该能力当迁移完成，也不再使用隐式宿主环境凭据。vendor只改import的既有约定保留，修正置于适配层；具体注入可行性实施时先探针。skills仍是开发者路径唯一维护源，本片只记录映射，不改正文；两路径语义对照测试，公众展示使用固定安全文案。
