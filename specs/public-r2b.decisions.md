# R2b 模块决定

对应[规格](public-r2b.md)、[计划](public-r2b.plan.md)、[交审](public-r2b.review.md)。上位依据总决定27与公众§4.1；决定30属于R2。本模块独立编号，历史追加，取代只加标记不改旧正文。

## 1. 规格先行与完整目标不缩减

甲方批准在public-r2b-plan仅编写四份规格文档，未批准实现；R2等待期间可提出独立前置片，但须另获批准。保留宿主无关完整A/B、真实provider、受控合成实证、可见配置和受限编排。fake完整旅程包括合成提交receipt及未知结果核查，不以“停在提交前”代替终态。R4/R5真实权限与提交边界不提前开放，skills正文不改。原因：避免把fake骨架、作者委托或配置参数当公众产品已完成。

## 2. 取消与费用必须按实际证据表达

本地停止、传输中断、远端确认和未知不是一个布尔值；多个事实可并存，远端模型取消不能撤回工具副作用。缺usage/费率显示未知，不显示0元或取消免费。不确定已执行保留核查，不自动重投。真实provider测试账号/版本/费率均未取得，本片不读现有凭据。原因：防止UI虚报停止及费用，保留现有恢复安全语义。

## 3. 语义保持的provider适配与模型边界

结构化结果和工具请求分开；两者都经原schema/当前状态校验。strict转换不能随意把默认字段改nullable；不支持明确失败，不暗降级。模型无shell/通用写/授权或提交通道；真实label/偏好不由模型伪造。discovery已有外发闸门，需迁移的是第二模型/隐式凭据路径，不把它误记为已证实local_only漏洞。包内已审核Node允许，不要求用户装npx，不运行时下载。

## 4. 分片与无循环出口

S1–S5可按依赖另审前置实施，S6依赖R2及前述片；R3依赖R2b，R2b出口不等待R3完整页面。R3消费协议需定义并经合成消费者验证；R2b自己的服务/模型/凭据状态/费用/停止界面必须接R2实测。全流程fake制品终态及至少一家真实provider实证仍硬性保留。全量分解估算15.5–27有效工作日，根路线/新总决定号由协调者处理，本片不抢根文件。原因：既允许可独立核心推进，也不让前置通过冒充整体通过。
