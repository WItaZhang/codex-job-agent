这是一个可以克隆到本地、在 Codex 或 Claude Code 中使用的求职助手项目。它从多个来源整理岗位，按你的偏好筛选推荐，再根据真实反馈调整偏好；需要投递时，可以导出清单，也可以让助手准备求职信、填写申请并按授权提交。

![产品流程：首次配置并初始化后，岗位发现与筛选形成候选岗位池；每日推荐用于浏览和反馈，当前投递清单用于自行投递或委托助手，两条流程均使用当前偏好。](docs/assets/product-overview.svg)

**推荐是用来了解机会、校准偏好的小样本；投递清单是符合条件的待投集合，不限于今天推荐的岗位。** 你可以只找岗位，也可以把流程延伸到投递。

## 快速开始

### 1. 下载项目

准备好 Git、[uv](https://docs.astral.sh/uv/getting-started/installation/)，以及你已能正常使用的 Codex 或 Claude Code。Python 3.13 可由 uv 按项目要求安装。

```sh
git clone https://github.com/WItaZhang/codex-job-agent.git
cd codex-job-agent
uv sync --locked
uv run playwright install chromium
```

### 2. 在助手中完成首次设置

在 Codex 中打开这个仓库，或从仓库目录运行 `codex` / `claude`。按宿主提示审阅项目配置并完成必要批准，然后发送下面这段话，把括号中的内容换成自己的需求：

> 我第一次使用这个项目，请帮我完成首次设置。
>
> 想找的岗位：[岗位或方向]；希望工作的地区：[国家或城市]；工作方式：[远程、混合或现场]；必须满足或需要排除的条件：[你的要求，没有就写无]。
>
> 请先检查依赖和项目工具连接，再按项目示例整理求职偏好与搜索设置。缺少的信息问我，不要把示例里的偏好当成我的。展示摘要，等我核对后保存并初始化。先不投递。

首次设置通过宿主助手协助完成：**检查连接 → 整理配置 → 核对摘要 → 初始化**。重点核对目标岗位、地点与排除条件；初始化成功后再使用每日推荐。

首次设置生成初始偏好与搜索配置；初始化后，当前偏好保存在本地数据库中。配置格式、连接排查以及用合成岗位试用的方法见[首次设置说明](docs/usage.md#首次设置)。初始化只做一次，之后通过反馈或明确的修改请求调整偏好。

## 日常使用

### 看今天的机会

使用 **`$today`（Codex）或 `/today`（Claude Code）**。当天还没有抓取时，助手会先发现岗位、去重预筛并打标签，再展示当天的推荐。

默认是 **7 个推荐 + 3 个探索**：推荐侧重当前偏好，探索提供其他可能。数量可配置，岗位不足时按实际数量展示。一天内以同一组推荐为主，不是每调用一次就换一批。

### 愿意时，给一点反馈

可以只浏览，也可以一行回复：

```text
1+ 2-坐班 3- 5+ 6?地点不对
```

| 回复 | 含义 | 助手如何处理 |
| --- | --- | --- |
| `+` | 想投 | 记录你的选择；与当前偏好不一致时分析原因 |
| `-` | 不想投，可附原因 | 记录反馈；与当前偏好不一致时分析原因、提出调整选项 |
| `?` | 岗位信息读错 | 核对并修正岗位标签，不改求职偏好 |

没提到的岗位不算反馈。修改偏好时，你可以选择方案、补充意见或这次不改；也可以明确授权助手依据已有反馈选择。调整会影响后续排序和投递清单。

### 需要时，整理待投岗位

使用 **`$apply-list` 或 `/apply-list`**，得到当前清单及 JSON / CSV 文件。清单结合当前推荐条件和你标记想投的岗位，处理拒绝反馈、重复岗位及投递状态；已投和已跳过的岗位不再列入。

**不必先完成今天的反馈。** 自行投完后，告诉助手“1–5 已投，7 跳过”，就能更新清单状态。

<details>
<summary>全部命令：按需要选择入口</summary>

| 目的 | Codex | Claude Code |
| --- | --- | --- |
| 只更新岗位库，不当场反馈 | `$fetch-jobs` | `/fetch-jobs` |
| 查看今日推荐、处理反馈 | `$today` | `/today` |
| 生成当前投递清单、更新已投或跳过 | `$apply-list` | `/apply-list` |
| 准备材料并按授权投递 | `$apply` | `/apply` |

这四个入口可以按需要使用。`today` 会按需调用岗位发现；`apply` 会自动生成当前清单，无需先手动运行 `apply-list`。

</details>

## 按需投递

先按[投递配置指南](docs/usage.md#投递)准备简历、个人资料、标准答案，以及需要“提交前确认”的公司名单。**当前投递后端需要 Claude Code CLI、Google Chrome 和 Node.js，即使前台使用 Codex 也一样。**

准备好后，用 `$apply` 或 `/apply`，并说清楚本次范围。例如“为这些岗位准备材料，只填不交”，或明确授权自动投递指定清单。助手会准备求职信 PDF、填写申请、上传材料并记录结果。

![投递规则：已授权的普通公司可以自动提交；需要提交前确认的公司和公司信息未知的岗位只填不交，留给用户本人提交。](docs/assets/application-boundaries.svg)

遇到登录、验证码或缺少个人信息时，助手会停下并说明需要处理什么；解决后可以恢复。随时可以说“停止投递”，已进入自动提交的岗位会完成当前提交后再停。保护公司在重试与恢复时仍然只填不交，由你检查并亲自提交。

## 使用前了解

- **岗位来源**：支持 Indeed、LinkedIn、Glassdoor、ZipRecruiter、Google Jobs 等来源，也支持可选招聘板和岗位 JSON 导入。网站、地区及访问条件会影响可用性。[来源与配置](docs/usage.md#岗位从哪里来)
- **资料与费用**：个人文件放在 Git 忽略的 `data/local/`。运行时模型会处理相应岗位、偏好或申请资料；宿主及可选模型服务的费用由你承担。[数据去向与费用](docs/usage.md#数据去向下载与费用)
- **投递边界**：不破解验证码，不填写 SSN 或支付信息，遇到仲裁协议会停下。自动提交无法撤回，请核对申请资料和授权范围。
- **当前验证范围**：macOS arm64 已验证双宿主接入与合成流程；Linux 有 CI 覆盖，桌面及投递未全面验证；Windows 未验证。真实招聘网站的投递效果取决于网站和账户环境。
